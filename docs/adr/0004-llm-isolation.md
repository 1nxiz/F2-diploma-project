## Context

Smart Booking Assistant приймає довільний текст користувача. Текст може містити помилки, неоднозначності та навмисні інструкції для моделі (prompt injection). Результатом обробки є дії зі спільним станом (hold, бронювання), тому неконтрольована поведінка LLM неприйнятна. LLM Provider є зовнішньою системою з непередбачуваною затримкою та доступністю.

## Alternatives

| # | Альтернатива | Обмеження |
| --- | --- | --- |
| A | LLM-агент з інструментами (function calling) для пошуку та бронювання | Модель ініціює дії зі станом; prompt injection може змінити параметри бронювання; поведінку важко протестувати детерміновано |
| B | Вільна текстова відповідь LLM + розбір регулярними виразами | Нестабільний формат; помилки розбору непомітні |
| **C** | **LLM лише як парсер у JSON за схемою `BookingConstraints`; перевірка Pydantic і доменними політиками; пошук, оптимізація, пояснення і бронювання — детермінований код** | LLM не використовується для пояснень і діалогу; потрібен резервний парсер |

## Decision

Обрано альтернативу **C**:

- Порт `ConstraintExtractor` має дві реалізації: `LlmConstraintExtractor` (OpenAI-сумісний API, режим Structured Output, температура 0) і `RuleBasedConstraintExtractor` (регулярні вирази та словник характеристик).
- LLM отримує системну інструкцію, текст запиту (≤ 500 символів), поточну дату й часовий пояс коворкінгу; ідентифікатори й email користувача не передаються.
- Відповідь приймається лише після валідації `BookingConstraints.model_validate_json` (поля з переліками, `extra = "forbid"`); помилка валідації → резервний парсер.
- Тайм-аут 5 с, 1 повтор, Circuit Breaker (5 помилок → 60 с на резервному парсері).
- LLM не має інструментів і не бачить даних каталогу; рішення про доступність, оцінку та бронювання приймає лише детермінований код.

## Consequences

**Позитивні:**

- Найгірший результат prompt injection — неправильні, але валідні за схемою обмеження, які користувач бачить перед підтвердженням; виконання дій від імені моделі неможливе.
- Система працює без LLM (деградація якості розбору, а не відмова функції).
- Оптимізація і пояснення тестуються детерміновано.

**Негативні та ризики:**

- **Залежність від зовнішнього провайдера** (затримка, доступність, зміна API); пом'якшено портом і можливістю локальної моделі (Ollama).
- **FinOps:** кожен запит — платний виклик API; оцінка для `gpt-4o-mini`-класу моделей — менше 1 цента за запит, але потрібен ліміт запитів асистента на користувача (20 / год).
- **Якість резервного парсера нижча:** складні формулювання («після обіду», «як минулого разу») не розпізнаються, і користувач отримує уточнювальне питання.
- **Приватність:** текст запиту залишає периметр системи; користувача попереджають у інтерфейсі, текст не містить ідентифікаторів.
