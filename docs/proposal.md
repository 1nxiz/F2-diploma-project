# Thesis Proposal

## 1. Попередня робоча назва проєкту

### Українською

**Проєктування та розробка вебсистеми бронювання робочих місць у коворкінгу**

### English

**Design and Development of a Web-Based Coworking Workspace Reservation System**

---

## 2. Актуальність та проблематика

Коворкінг-простори мають обмежену кількість робочих місць та інших ресурсів, доступність яких залежить від часу, типу ресурсу та поточних бронювань. За відсутності централізованої інформаційної системи керування такими ресурсами ускладнюється контроль їх доступності та підвищується ризик конфліктів під час одночасного бронювання.

Основною інженерною проблемою є забезпечення коректного керування станом ресурсів при конкурентному доступі. Система повинна запобігати створенню перетинних бронювань для одного робочого місця, забезпечувати узгодженість даних та коректно обробляти одночасні запити користувачів.

Додатковими інженерними завданнями є реалізація автентифікації та авторизації, автоматизованого тестування, контейнеризованого розгортання, CI-процесів та базових засобів контролю якості програмного забезпечення.

---

## 3. Ідея та призначення програмного продукту

Програмний продукт є вебсистемою керування та бронювання робочих місць у коворкінгу.

Система забезпечує централізоване зберігання інформації про робочі місця, їх характеристики, часову доступність та бронювання. Користувач може переглядати доступні робочі місця, вибирати часовий інтервал та створювати або скасовувати власні бронювання.

Архітектура системи базується на клієнт-серверній моделі. Frontend взаємодіє з backend через REST API. Backend реалізується як модульний моноліт на основі FastAPI з функціональним розділенням відповідальності між модулями.

PostgreSQL використовується як основне персистентне сховище та джерело узгодженого стану даних. Redis використовується як механізм короткочасної координації конкурентних операцій під час створення бронювання.

Коректність бронювання не залежить виключно від Redis. Остаточна цілісність даних забезпечується транзакційною обробкою та обмеженнями на рівні PostgreSQL.

Основний архітектурний напрям проєкту — **розподілені системи та Cloud-Native мікросервісні архітектури**.

## 4. Core Features

### 4.1. Автентифікація та авторизація

Система забезпечує реєстрацію, автентифікацію та авторизацію користувачів.

Для захисту API використовується JWT-based authentication. Доступ до функціональності системи визначається відповідно до ролі користувача.

Передбачаються такі основні ролі:

* User;
* Admin.

Адміністративні операції доступні лише користувачам із відповідними правами.

### 4.2. Каталог робочих місць

Користувач може переглядати доступні робочі місця та їх характеристики.

Для кожного робочого місця зберігається інформація про:

* ідентифікатор;
* тип робочого місця;
* зону розташування;
* доступне обладнання;
* поточний статус;
* доступність для бронювання.

### 4.3. Пошук та фільтрація ресурсів

Система надає можливість фільтрувати робочі місця за визначеними характеристиками та часовим інтервалом.

Результат пошуку формується з урахуванням існуючих бронювань та поточного стану ресурсів.

### 4.4. Створення та скасування бронювання

Авторизований користувач може створити бронювання робочого місця на визначену дату та часовий інтервал.

Перед створенням бронювання система перевіряє доступність ресурсу та не допускає створення конфліктних бронювань.

Користувач також може скасувати власне активне бронювання відповідно до правил системи.

Для захисту від повторного виконання одного запиту передбачається використання механізму idempotency key.

### 4.5. Конкурентне бронювання та контроль цілісності

Система повинна коректно обробляти одночасні запити на бронювання одного ресурсу.

Для координації конкурентних операцій використовується Redis. Блокування встановлюється атомарною операцією з унікальним токеном власника та обмеженим TTL.

Redis використовується як механізм координації та зменшення кількості конфліктних операцій, але не є єдиною гарантією цілісності даних.

PostgreSQL забезпечує транзакційне збереження бронювання та остаточний контроль перетинних часових інтервалів на рівні бази даних.

У разі недоступності Redis система повинна мати визначену поведінку деградації та не створювати некоректних бронювань.

### 4.6. Особистий кабінет користувача

Користувач може переглядати власні активні та завершені бронювання.

Для кожного бронювання відображаються:

* робоче місце;
* дата;
* часовий інтервал;
* статус бронювання.

Історія бронювань зберігається для подальшого перегляду.

### 4.7. Адміністративне керування

Адміністратор може керувати робочими місцями, їх характеристиками, доступністю та бронюваннями.

Адміністративні операції захищаються механізмом рольової авторизації.

## 5. Архітектурні рішення

Система реалізується за клієнт-серверною моделлю з модульною організацією backend.

Основні компоненти:

* React frontend;
* FastAPI backend;
* PostgreSQL;
* Redis;
* Docker infrastructure.

Backend організований як модульний моноліт із функціональними модулями:

* Authentication;
* Users;
* Workspaces;
* Bookings;
* Administration.

Взаємодія frontend та backend здійснюється через REST API.

Для роботи з базою даних використовується SQLAlchemy, міграції структури бази даних виконуються за допомогою Alembic.

Архітектурні рішення документуються за допомогою C4 Model та Architecture Decision Records (ADR).

## 7. Інженерна складова проєкту

Основний інженерний фокус проєкту полягає у забезпеченні коректної роботи системи при конкурентному доступі до обмежених ресурсів.

Ключовими інженерними аспектами є:

* контроль конкурентного доступу;
* забезпечення узгодженості даних;
* транзакційна обробка операцій бронювання;
* контроль перетинних часових інтервалів на рівні PostgreSQL;
* ідемпотентність операцій;
* Application Security;
* автоматизоване тестування;
* навантажувальне тестування;
* контейнеризація;
* автоматизація CI;
* базова Observability;
* архітектурна документація.

Для перевірки механізму конкурентного бронювання передбачається використання k6-сценарію, у якому декілька віртуальних користувачів одночасно надсилають запити на бронювання одного робочого місця та часового інтервалу.

Очікуваним результатом тесту є створення лише одного успішного бронювання та відхилення конфліктних запитів.

Життєвий цикл проєкту охоплює аналіз предметної області, архітектурне проєктування, реалізацію frontend та backend, тестування, контейнеризацію, автоматизацію CI та документування архітектурних рішень.

## 9. Очікуваний результат

Результатом кваліфікаційного проєкту має стати функціональна вебсистема бронювання робочих місць у коворкінгу з REST API, реляційним сховищем даних, механізмами контролю конкурентного доступу, рольовою авторизацією, автоматизованим тестуванням та контейнеризованою інфраструктурою.

Проєкт також має містити CI-процес для автоматизованої перевірки коду та тестів, навантажувальний сценарій для перевірки конкурентного бронювання, базові засоби Observability та архітектурну документацію у форматах C4 Model і ADR.
