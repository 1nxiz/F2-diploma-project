# ВСТУП

## Актуальність теми

Системи бронювання спільних ресурсів (робочих місць, переговорних кімнат) належать до класу інформаційних систем із конкурентним доступом до обмеженого ресурсу, прив'язаного до часового інтервалу. У пікові періоди кілька клієнтів одночасно ініціюють операції над тим самим ресурсом. За реалізації операції бронювання за схемою «перевірити доступність — записати» без синхронізації виникає стан гонитви (race condition), наслідком якого є подвійне бронювання та порушення цілісності даних. Ручний облік і табличні засоби не забезпечують ні атомарності операцій, ні актуальності стану ресурсів у реальному часі.

Ключова інженерна задача полягає у забезпеченні узгодженості стану ресурсів за паралельних запитів без суттєвого зростання затримки (latency) відповіді API. Поєднання реляційного сховища з транзакційними гарантіями ACID та обмеженнями цілісності на рівні схеми даних (PostgreSQL), розподіленого короткочасного блокування з обмеженим часом життя (Redis) і stateless REST API (FastAPI) дає змогу усунути конфлікти бронювання, зберегти можливість горизонтального масштабування застосунку та автоматично звільняти ресурс у разі відмови процесу, що утримує блокування. Додатковими вимогами є рольове розмежування доступу (JWT, RBAC), автоматизований контроль якості коду в конвеєрі CI/CD та відтворюване контейнеризоване розгортання. Сукупність зазначених вимог зумовлює актуальність теми кваліфікаційної роботи.

## Об'єкт дослідження

Процес керування доступністю та конкурентного бронювання спільних робочих ресурсів коворкінгу в клієнт-серверному вебсередовищі.

## Предмет дослідження

Методи та засоби забезпечення узгодженості стану ресурсів під час конкурентного бронювання: розподілене блокування з обмеженим часом життя на основі Redis, транзакційна модель та обмеження цілісності PostgreSQL, шарова архітектура REST API на FastAPI з патернами Repository та Dependency Injection, рольова модель доступу на основі JWT, а також контейнеризація (Docker) та автоматизований конвеєр CI/CD (GitHub Actions).

## Мета роботи

Проєктування та розробка вебсистеми бронювання робочих місць коворкінгу на основі FastAPI, PostgreSQL і Redis із механізмом розподіленого блокування ресурсів для усунення конфліктів подвійного бронювання та забезпечення узгодженості даних за конкурентного доступу.

## Завдання проєкту

Для досягнення поставленої мети необхідно виконати такі завдання:

1. Проаналізувати предметну область і наявні програмні аналоги систем бронювання спільних ресурсів, сформулювати функціональні та нефункціональні вимоги й технічне завдання.
2. Обґрунтувати вибір технологічного стеку (FastAPI, PostgreSQL, Redis, React, Docker) та архітектурного стилю системи із фіксацією рішень у форматі Architecture Decision Records (ADR).
3. Спроєктувати архітектуру системи з використанням нотацій UML та C4 Model (рівні контексту, контейнерів і компонентів) та логічну модель даних.
4. Розробити алгоритм атомарного створення бронювання з розподіленим блокуванням ресурсу в Redis, перевіркою перетину часових інтервалів і транзакційним записом у PostgreSQL.
5. Спроєктувати та реалізувати клієнтський інтерфейс, REST API та схему контейнеризованого розгортання на основі Docker Compose із конвеєром CI/CD у GitHub Actions.
6. Провести інструментальний аудит якості програмного коду шляхом модульного, інтеграційного та навантажувального тестування (Pytest, k6) з оцінкою коректності роботи системи за конкурентних запитів.
7. Апробувати результати роботи у формі наукової статті або тез доповіді на науково-практичній конференції.
